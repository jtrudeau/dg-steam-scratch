Debug Like a Scientist

debuggingeventslogic

A quick protocol for hunting bugs: observe, predict, isolate, and retest with intention.

Steps

  1. Pause and observe: Click the green flag and list what you expected vs. what actually happened before touching any code.
  2. Isolate one script: Right-click → duplicate a sprite or disable one script at a time to see if the bug follows.
  3. Add print-style clues: Drop `say` blocks or temporary color changes inside loops so you know which blocks are running.
  4. Check events and resets: Make sure green flag scripts set starting positions/variables and broadcasts match exactly.
  5. Retest and log: After each tweak, retest and jot one sentence in your debugging log so you can roll back or teach peers.

Guide

Start with one sentence

Before moving blocks, say:

I expected ___, but ___ happened.

If you cannot fill in the blanks, run the project again and watch carefully.

The debug loop

  1. Reproduce the bug.
  2. Test one sprite.
  3. Test one script.
  4. Change one thing.
  5. Run the same test again.

Scratch checks that fix most beginner bugs

CheckWhy it matters
Correct sprite selectedCode only affects the sprite it is attached to
Hat block connectedScripts need an event to start
Green flag resetVariables and positions should start clean
Show/hide stateA hidden sprite can still run code
Broadcast spellingMessages must match exactly
Clone cleanupToo many clones can slow a project

Temporary debug blocks

Use these while testing, then remove them.

say [Debug: this script ran] for (1) seconds
say (join [score: ] (score)) for (1) seconds

Done when

You can explain the bug, show the exact script you tested, and describe the fix.
