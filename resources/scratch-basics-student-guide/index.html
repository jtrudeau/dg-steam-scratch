Scratch Basics Student Guide

basicseventsmotionvariablesdebugging

A complete Grade 6 guide for learning the Scratch editor, building a first interactive project, debugging it, and knowing what to practice next.

Steps

  1. Tour the editor: Learn the stage, sprite list, blocks palette, script area, and tabs without guessing where to click.
  2. Build Tiny Quest: Create one small playable project using events, motion, looks, sensing, variables, broadcasts, and clones.
  3. Debug like a builder: Use a calm test loop to find bugs, explain them, and fix one thing at a time.
  4. Remix with purpose: Choose a theme, add one meaningful feature, and credit anything you reuse.
  5. Check mastery: Use the exit checklist to know when you are ready for team projects.

Guide

What this guide is

This is your Scratch basics map. If you are in Grade 6 and you can read this page, you can build the project. You do not need to memorize every block. You need to learn how to find blocks, snap them together, test often, and fix one problem at a time.

By the end, you will have a small interactive project called Tiny Quest:

  • A player sprite moves with the arrow keys.
  • A guide sprite explains the goal.
  • The score changes when you touch a collectible.
  • A message switches the scene when the goal is reached.
  • A few clones make the world feel alive.

The builder loop

Use this loop every time you code:

  1. Predict: Say what should happen.
  2. Build: Add 2-5 blocks.
  3. Test: Click the green flag or press the key.
  4. Notice: What happened? What was different from your prediction?
  5. Improve: Change one thing, then test again.

Good Scratch creators do not avoid mistakes. They make mistakes easy to see.

Safety and sharing rules

Scratch projects can be public, so keep your project safe:

  • Use first names, initials, or team names only.
  • Do not put phone numbers, addresses, private emails, or school details in a project.
  • Give credit if you remix code, art, sounds, or ideas.
  • Feedback should name one thing that works and one thing to improve.

Tiny Quest setup

Create a new Scratch project. Rename it Tiny Quest - Your Name or Team.

Add these sprites:

  • Player: any character the player controls.
  • Guide: a sprite that gives instructions.
  • Star: a collectible.

Add these backdrops:

  • Start: a simple first scene.
  • Win: a celebration scene.

Create two variables for all sprites:

  • score
  • goal

Step 1: Start clean every time

Put this on the Player sprite.

when green flag clicked
set [score v] to (0)
set [goal v] to (5)
go to x: (0) y: (-80)
show

Why this matters: the green flag should reset important values and positions. If your project only works the second time, you probably forgot a reset block.

Step 2: Make the guide explain the goal

Put this on the Guide sprite.

when green flag clicked
show
go to x: (-120) y: (120)
say [Collect 5 stars. Use arrow keys to move.] for (4) seconds

Now test. The guide should appear and explain the game.

Step 3: Move with arrow keys

Put this on the Player sprite.

when green flag clicked
forever
  if <key [right arrow v] pressed?> then
    change x by (6)
  end
  if <key [left arrow v] pressed?> then
    change x by (-6)
  end
  if <key [up arrow v] pressed?> then
    change y by (6)
  end
  if <key [down arrow v] pressed?> then
    change y by (-6)
  end
end

Test before adding anything else. If movement feels too fast, change 6 to 4. If it feels slow, change it to 8.

Step 4: Keep the player on screen

Add this inside the same forever loop, after the arrow checks.

if on edge, bounce

If your player flips upside down, select the sprite and set rotation style to left-right or do not rotate.

Step 5: Make the star collectible

Put this on the Star sprite.

when green flag clicked
show
go to x: (pick random (-180) to (180)) y: (pick random (-120) to (120))
forever
  if <touching [Player v]?> then
    change [score v] by (1)
    go to x: (pick random (-180) to (180)) y: (pick random (-120) to (120))
  end
end

Test your project. You should be able to collect stars and increase the score.

Step 6: Win with a broadcast

Put this on the Star sprite, inside the same forever loop after the score changes.

if <(score) = (goal)> then
  broadcast [win v]
end

Put this on the Stage.

when green flag clicked
switch backdrop to [Start v]

when I receive [win v]
switch backdrop to [Win v]

Put this on the Guide sprite.

when I receive [win v]
say [You did it! Now remix one thing.] for (3) seconds

Broadcasts are messages. One sprite sends the message, and any sprite can listen for it.

Step 7: Add animation

Put this on the Player sprite if it has at least two costumes.

when green flag clicked
forever
  next costume
  wait (0.2) seconds
end

Small visual feedback makes a project feel alive. Do not add too many effects before the game works.

Step 8: Add star clones

Once one star works, make it more interesting with clones. Put this on the Star sprite.

when green flag clicked
hide
forever
  create clone of [myself v]
  wait (1) seconds
end

Add this to the Star sprite too.

when I start as a clone
show
go to x: (pick random (-200) to (200)) y: (170)
repeat until <(y position) < (-170)>
  change y by (-5)
  if <touching [Player v]?> then
    change [score v] by (1)
    if <(score) = (goal)> then
      broadcast [win v]
    end
    delete this clone
  end
  wait (0.05) seconds
end
delete this clone

Important: if you use clones, remove or stop the older forever script that moves the original star around. One clear system is easier to debug than two systems fighting each other.

Step 9: Add one smart choice

Use ask when you want the player to type an answer.

Put this on the Guide sprite.

when [space v] key pressed
ask [What should this quest help people learn?] and wait
say (join [Your mission: ] (answer)) for (4) seconds

Now your project can connect to a topic: recycling, health, kindness, city design, water, animals, space, or any idea your team cares about.

Debugging checklist

When something breaks, do this in order:

  1. Read the selected sprite name. Are you editing the correct sprite?
  2. Click the stack. Does that exact stack run by itself?
  3. Check the hat block. Does the script start with green flag, key press, clone start, or receive message?
  4. Check spelling. Broadcast names and variable names must match.
  5. Reset values. Variables, positions, size, show/hide, and backdrop should reset on green flag.
  6. Use a temporary say block. Make the sprite report where the code got to.

Temporary debug block:

say [Debug: I reached this script] for (1) seconds

Remove debug blocks after the bug is fixed.

Make Tiny Quest your own

Choose one theme:

  • Sustainable city: collect clean energy icons and avoid pollution.
  • Healthy habits: collect sleep, water, movement, and kindness points.
  • Space rescue: collect oxygen while avoiding debris.
  • Animal care: collect food and habitat items.
  • Mystery story: collect clues to unlock the ending.

Choose one stretch feature:

  • Add a 30-second timer.
  • Add a bad item that subtracts 1 point.
  • Add a start screen with instructions.
  • Add sound effects for collect and win.
  • Add two levels with different backdrops.
  • Add a restart button.

Only add one stretch feature at a time. Finish, test, then add the next.

Mastery ladder

You are ready for team projects when you can honestly say:

  • I can create a sprite and put code on the correct sprite.
  • I can use the green flag to reset my project.
  • I can move a sprite with keys or clicks.
  • I can use a variable for score, timer, lives, or progress.
  • I can use an if block to check touching, keys, or values.
  • I can use a broadcast to move from one scene to another.
  • I can explain one bug and how I fixed it.
  • I can remix respectfully and give credit.
