Scratch Interface Tour

spritesstageeventsbasics

A Grade 6 walkthrough of the Scratch editor so new makers know where to click, what each area controls, and how to recover when something does not work.

Steps

  1. Stage (right side): Run the project with the green flag and stop it with the red stop button. Watch what changes.
  2. Sprites list: Click the exact character or object you want to edit before adding code.
  3. Blocks palette: Use the color categories to find blocks: Events start scripts, Motion moves, Looks changes appearance, Control repeats/checks.
  4. Scripts area: Snap blocks under a hat block. Click a stack to test just that stack.
  5. Code / Costumes / Sounds tabs: Use Code for logic, Costumes for art changes, and Sounds for feedback.

Guide

Learn the editor by building one tiny test

Open Scratch and create a new project. Do not worry about making something impressive yet. Your goal is to learn where things are.

1. Stage

The Stage is where the audience sees your project. The green flag starts scripts. The red stop button stops scripts.

Try this:

  1. Click the green flag.
  2. Click the red stop button.
  3. Say out loud: "The stage is where the project runs."

2. Sprite list

A sprite is a character or object. The sprite list is usually under the stage. Click a sprite before you add code, costumes, or sounds.

Beginner rule: if the wrong sprite moves or talks, you probably put the code on the wrong sprite.

3. Blocks palette

Blocks are grouped by color:

CategoryUse it for
EventsStarting scripts with green flag, key press, click, or message
MotionMoving and positioning sprites
LooksSpeech bubbles, costumes, size, effects, show/hide
SoundMusic and sound effects
ControlWaits, loops, if checks, clones
SensingTouching, keys, mouse, answers
OperatorsMath, comparisons, random choices, joining text
VariablesScore, timer, lives, scene number
My BlocksCustom reusable actions

4. Scripts area

The scripts area is the workspace where blocks snap together. Most scripts start with a hat block, which has a rounded top.

Build this on the sprite that is selected:

when green flag clicked
say [I know where my code is!] for (2) seconds
move (20) steps

Test it. Then click only the stack of blocks. The stack should run even without the green flag. That is useful for quick testing.

5. Code, Costumes, Sounds

Use the tabs like this:

  • Code: make the project do things.
  • Costumes: change how the sprite looks.
  • Sounds: add feedback when something happens.

Try a costume change:

when [space v] key pressed
next costume
say [New look!] for (1) seconds

Fast recovery checklist

When Scratch feels confusing, check these in order:

  1. Is the correct sprite selected?
  2. Is the script connected under a hat block?
  3. Did you click the green flag or press the correct key?
  4. Is the sprite hidden, too small, or off the stage?
  5. Did you accidentally put code in the Backdrop instead of a sprite?

Done when

You can point to the stage, sprite list, blocks palette, scripts area, Code tab, Costumes tab, and Sounds tab, and explain what each one does.
