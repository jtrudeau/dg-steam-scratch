Broadcast + Receive Patterns

broadcasteventscoordination

Coordinate sprites and scenes using named messages so your story stays in sync.

Steps

  1. Name messages clearly: Use labels like `start-level`, `win`, `game-over`, or `scene-2` instead of generic names.
  2. One source of truth: Keep scene changes in one script that broadcasts; other sprites just listen and react.
  3. Chain sequences: Broadcast from within a listener to trigger the next step (e.g., intro → gameplay → outro).
  4. Handle duplicates: If two things fire at once, add small waits (0.2s) or separate messages to avoid clashes.
  5. Debug with logs: Temporarily `say` the message name inside each listener to verify everyone hears it.

Guide

What broadcast means

A broadcast is a message inside your Scratch project. One script sends the message. Any script with a matching when I receive hat can react.

Use broadcasts when one event should affect more than one sprite.

Basic pattern

Sender:

when this sprite clicked
broadcast [start-game v]

Receiver:

when I receive [start-game v]
say [Game started!] for (1) seconds

Scene pattern

Put this on the Stage.

when green flag clicked
switch backdrop to [Start v]

when I receive [start-game v]
switch backdrop to [Game v]

when I receive [game-over v]
switch backdrop to [Game Over v]

Debug checklist

  • Did the sender script run?
  • Do the message names match exactly?
  • Is the receiver using when I receive, not green flag?
  • Is the sprite hidden when you expected to see it?

Done when

You can use one broadcast to change the backdrop and make at least one sprite react.
