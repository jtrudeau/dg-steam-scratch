Clones + Spawners

clonesspawning

Generate repeated objects like coins, enemies, or particles without copy-paste.

Milestones

  1. Spawn: Create clones with spacing or timing rules.
  2. Control: Give each clone its own movement or behavior.
  3. Cleanup: Delete clones when they are no longer needed.

Guide

Goal

Use clones to build dynamic scenes with less manual work. A clone is a temporary copy of a sprite. It is useful for coins, falling items, enemies, particles, and repeated decorations.

Clone roles

  • Original sprite: usually hides and creates clones.
  • Clone: shows, moves, checks collisions, then deletes itself.
  • Cleanup: every clone needs a way to disappear.

Try it

Create a clone every second and move it across the screen.

when green flag clicked
forever
  create clone of [myself v]
  wait (1) seconds
end
when I start as a clone
  go to x: (-220) y: (0)
  glide (2) secs to x: (220) y: (0)
  delete this clone

Falling collectible pattern

This is a strong starter pattern for games.

when green flag clicked
hide
forever
  create clone of [myself v]
  wait (1) seconds
end

when I start as a clone
show
go to x: (pick random (-200) to (200)) y: (170)
repeat until <(y position) < (-170)>
  change y by (-5)
  if <touching [Player v]?> then
    change [score v] by (1)
    delete this clone
  end
  wait (0.05) seconds
end
delete this clone

Avoid clone overload

If a project slows down:

  • Increase the wait between clone creation.
  • Delete clones when they touch the edge, player, or ground.
  • Do not create clones inside a forever loop without a wait.
  • Hide the original sprite if only clones should appear.

Checkpoint

Clones appear, do their job, and disappear without slowing the project.
