Broadcasts + Scene Control

broadcastcoordination

Coordinate multiple sprites with broadcast messages and listeners.

Milestones

  1. Signal: Broadcast a message when something important happens.
  2. Listen: Use when I receive to respond in other sprites.
  3. Chain: Trigger the next scene with a second broadcast.

Guide

Goal

Keep sprites and scenes in sync using messages. A broadcast is like a project announcement: one script sends it, and any script that hears it can respond.

When to use broadcasts

Use broadcasts when:

  • A level starts or ends.
  • A player wins or loses.
  • A button changes the scene.
  • One sprite needs another sprite to react.
  • You want to avoid messy timing tricks like "wait 7 seconds and hope."

Name messages clearly: start-game, win, game-over, next-scene, restart.

Try it

Broadcast a message to change a backdrop and start a new sprite action.

when green flag clicked
broadcast [scene-2 v]
when I receive [scene-2 v]
switch backdrop to [ocean v]

Build a clean scene system

Put this on the Stage.

when green flag clicked
switch backdrop to [Start v]

when I receive [play v]
switch backdrop to [Game v]

when I receive [win v]
switch backdrop to [Win v]

Put this on a start button sprite.

when this sprite clicked
broadcast [play v]
hide

Put this on a guide sprite.

when I receive [play v]
say [Collect 5 points to win.] for (3) seconds

when I receive [win v]
say [Great work!] for (2) seconds

Broadcast debugging

If listeners do not react:

  1. Check that the sender actually runs.
  2. Check that the message names match exactly.
  3. Make sure the receiving script starts with when I receive.
  4. Add a temporary say [heard win] block inside the listener.

Design rule

Use broadcasts for meaning, not delay. broadcast [win] is clearer than wait (12) seconds.

Checkpoint

You can coordinate the stage and at least two sprites without timing hacks.
