Scratch Guide: Start Here

overviewworkflowdebugging

The learning map for new Scratch builders: how to practice, what to build first, how to debug, and when to move on.

Milestones

  1. Open the complete guide: Use the Scratch Basics Student Guide as the main path if you are new or stuck.
  2. Practice in tiny loops: Predict, build 2-5 blocks, test, notice, and improve before adding more.
  3. Save evidence: After each module, keep one screenshot and one sentence explaining what changed.
  4. Debug calmly: Check the selected sprite, event block, variable reset, and broadcast spelling before asking for help.

Guide

Goal

Learn how to use this Scratch guide like a builder, not like a worksheet. You will make small pieces, test them, explain what happened, and then improve them.

If you are brand new, start with the complete student guide:

Open the Scratch Basics Student Guide

The 5-step practice loop

Use this loop for every module:

  1. Predict: Say what you expect the code to do.
  2. Build: Add only a few blocks.
  3. Test: Run the project right away.
  4. Notice: Name what worked and what surprised you.
  5. Improve: Change one thing and test again.

This is how real programmers work. They do not write a giant project and hope it works at the end.

Try it

Make a tiny script so you can prove that your project can start, speak, change, and reset.

when green flag clicked
go to x: (0) y: (0)
say [I am ready to build!] for (2) seconds
change color effect by (25)
wait (1) seconds
clear graphic effects

Now change the message. Test again. If it changes, you are editing the correct sprite.

Your build log

After each module, write one line:

ModuleScreenshot saved?One-sentence proof
Events + TimingYes / NoMy sprite starts with the flag and reacts to a key.

The sentence matters because it shows you understand the behavior, not just the blocks.

Stuck protocol

Before asking for help, check:

  • Is the correct sprite selected?
  • Does the script start with the event you are testing?
  • Did you click the green flag after changing code?
  • Did variables reset to the right starting value?
  • Are broadcast names spelled exactly the same?
  • Can a say [Debug] for (1) seconds block prove the script runs?

Checkpoint

You can run a script, make a change, re-test, and explain what changed without help.
