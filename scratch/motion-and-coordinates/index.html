Motion + Coordinates

motioncoordinates

Move sprites precisely using steps, x/y positions, and boundaries.

Milestones

  1. Move: Use steps for simple movement and glide for smooth motion.
  2. Place: Use x/y to position sprites consistently.
  3. Boundaries: Keep sprites on screen with simple if-then rules.

Guide

Goal

Control where a sprite is and where it goes. Scratch uses an x/y grid: x moves left and right, y moves down and up.

The stage grid

  • Center is x: 0 y: 0.
  • Left side is negative x. Right side is positive x.
  • Bottom is negative y. Top is positive y.
  • Use go to x: y: when you need an exact starting position.
  • Use change x by and change y by for smooth controls.

Try it

Create a sprite that moves in a square.

when green flag clicked
go to x: (0) y: (0)
repeat (4)
  move (80) steps
  turn right (90) degrees
end

Build keyboard movement

This is the most useful beginner movement pattern for games.

when green flag clicked
go to x: (0) y: (0)
forever
  if <key [right arrow v] pressed?> then
    change x by (5)
  end
  if <key [left arrow v] pressed?> then
    change x by (-5)
  end
  if <key [up arrow v] pressed?> then
    change y by (5)
  end
  if <key [down arrow v] pressed?> then
    change y by (-5)
  end
  if on edge, bounce
end

Common motion bugs

  • Sprite starts in a weird place: add a go to x: y: reset under the green flag.
  • Sprite spins around: set rotation style to left-right or do not rotate.
  • Sprite disappears: use go to x: (0) y: (0) to bring it back.
  • Movement is too fast: lower the change amount from 5 to 3.

Level up

Make a target spot. When the player touches it, celebrate.

if <touching [Target v]?> then
  say [Goal!] for (1) seconds
end

Checkpoint

You can send a sprite to exact positions, move it with keys, and reset it when the green flag starts.
