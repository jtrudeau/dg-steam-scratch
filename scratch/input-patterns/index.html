Input Patterns

inputcontrols

Build reliable keyboard and mouse controls that feel responsive.

Milestones

  1. Map keys: Choose clear controls and document them on screen.
  2. Hold vs tap: Use forever loops for hold controls, events for taps.
  3. Debounce: Add short waits to prevent accidental repeats.

Guide

Goal

Create control schemes that match your game or story. Good input feels predictable: the same key always does the same kind of action.

Tap vs hold

  • Use when [key] key pressed for a tap action like jump, talk, attack, or open menu.
  • Use forever plus key pressed? for hold controls like walking, steering, or aiming.
  • Put instructions on the start screen so players do not guess.

Try it

Build left/right movement with a loop that checks keys.

when green flag clicked
forever
  if <key [left arrow v] pressed?> then
    change x by (-5)
  end
  if <key [right arrow v] pressed?> then
    change x by (5)
  end
end

Add a tap action

Use a separate event when one press should do one action.

when [space v] key pressed
say [Action!] for (1) seconds

Add a simple cooldown

If a tap repeats too fast, add a small wait.

when [space v] key pressed
change [energy v] by (-1)
wait (0.3) seconds

Pick controls that are easy to remember. Do not make the player use too many keys at once.

Checkpoint

You can explain the difference between tap and hold controls and choose the right pattern for each action.
