Variables + State

variablesstate

Track scores, timers, and story progress using variables.

Milestones

  1. Create: Name variables clearly and set them at the start.
  2. Change: Add and subtract points or time.
  3. Display: Show or hide variables based on the scene.

Guide

Goal

Store and update values that matter to your project. A variable is a labeled memory box. Use it for score, timer, lives, level, energy, or story progress.

The golden rule

Always set important variables at the start.

If a score starts at last round's number, the project feels broken. A green flag script should reset your state.

Try it

Build a score counter that resets when the flag is clicked.

when green flag clicked
set [score v] to (0)

Then add points when something happens.

when this sprite clicked
change [score v] by (1)

Build lives

Create a variable called lives.

when green flag clicked
set [lives v] to (3)

when I receive [hit v]
change [lives v] by (-1)
if <(lives) = (0)> then
  broadcast [game-over v]
end

Build a timer

Create a variable called timer.

when green flag clicked
set [timer v] to (30)
repeat until <(timer) = (0)>
  wait (1) seconds
  change [timer v] by (-1)
end
broadcast [time-up v]

Common variable bugs

  • Score keeps old value: add set [score] to (0) under the green flag.
  • Variable changes too fast: it is probably inside a forever loop without a wait or touch guard.
  • Wrong sprite changes it: choose "for all sprites" when the whole project needs the value.
  • Hard to read: rename vague variables like thing to score, timer, or level.

Checkpoint

Your variables reset reliably, change only when intended, and help the player understand progress.
